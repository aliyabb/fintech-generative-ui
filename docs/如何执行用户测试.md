# 怎么把这个测试跑完（约 1 小时）

工具已经就绪，剩下的只有"找 6 个人"。这份文档把流程压到最短。

## 一、发给被试的话（直接复制）

> 帮个忙，10 分钟。我在测一个金融产品的说明写得清不清楚，
> 需要几个**没有金融背景**的人来看。
> 打开这个链接，按提示做完，最后把生成的一段文字发我就行。
> 没有对错，测的是说明不是你。
>
> https://aliyabb.github.io/fintech-generative-ui/usertest.html
>
> 打开后先填一个编号，我给你的是 **P1**（每人不同，别重复）。

**被试条件**：过去一年用过信用卡或消费分期；**不是**金融从业者。
6 人即可，8 人更好。编号务必从 P1 顺序发，不要跳号——
奇偶决定先看文字还是先看界面，跳号会让两种条件人数不均。

## 二、收到结果后

每人会发回一段 JSON。存成文件放进 `usertest_data/`：

```
usertest_data/P1.json
usertest_data/P2.json
...
```

然后跑一条命令：

```bash
python3 src/analyze_usertest.py
```

它会输出正确率、中位耗时、信心评分、分任务明细和逐人原始数据，
同时写入 `results/user_test.json`。

## 三、把结果接进项目

```bash
python3 src/build_site.py
```

演示页和 README 里现在标注"未测量"的三行会自动填上真实数字。
**没有数据时脚本不产出任何指标**——这是刻意的。

## 四、报告结果时要一起说的话

样本量只有 6–8 人，**不足以做统计推断**。能说的是：

- ✅ "6 人中有 5 人在界面条件下答对了真实年化，文字条件下只有 2 人"
- ✅ "所有人在文字条件下都需要往回翻，界面条件下没有人翻"
- ❌ "生成式 UI 让理解度提升了 30%"（这个精度这个样本量支撑不了）

逐人原始数据会一并输出，报告时把它附上，而不是只给平均值。

## 五、预设的失败情形（测之前就写好了）

见 [用户测试方案](用户测试方案.md) 最后一节。写在前面是为了避免
拿到数据后再倒推解释——那样测了等于没测。
